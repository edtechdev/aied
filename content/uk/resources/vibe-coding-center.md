*Автоматичний переклад цієї англійської сторінки, не перевірений носієм мови.*

**The Vibe-Coding Center** — безкоштовний польовий посібник Miguel Guhlin для вчителя, який хоче [[vibe-coding|вайб-кодувати]] маленький статичний освітній сайт з асистентом для програмування — вихідний квиток, тест, портфоліо класу — і не випустити разом із ним відкритий ключ API чи дані студентів.

## Що з цим можна робити

Настанову несуть три файли інструкцій: `WEB_DESIGN.md`, `EDU_COMPLIANCE.md` і `securevcc.md`. Завантажте їх у корінь проєкту, заповніть шаблон брифу проєкту, а потім попросіть асистента прочитати й застосувати всі три; посібник прямо каже, що присутність не є активацією, тож файли треба назвати в запиті. Зрозумілі посібники пояснюють кожен із них, зокрема проходження «Три суттєві перевірки перед поширенням»: збирайте менше даних студентів, перевірте відкритий ключ API й пристосуйте дизайн інструмента до його навчального завдання. Повний набір додає сам сайт, пакет промптів, огляд перед запуском і скрипти перезбирання, а також маніфест SHA-256 для завантаження.

Супутня сторінка [прикладів EduSynth Hub](https://mguhlin.github.io/funquiz/examples.html) показує результати як робочі статичні інструменти, а не як знімки екрана: генератор вихідних квитків, що пише питання на вибраному рівні таксономії SOLO, студентське портфоліо в одному HTML-файлі на GitHub Pages і пошукова бібліотека ресурсів для професійного розвитку — усе працює на боці клієнта без входу в LMS.

## Для кого це

Учителі та [[learning-design|дизайнери навчання]] в K-12 і вищій освіті, які можуть описати потрібний інструмент і готові перевірити, що створив асистент. Він також пасує кафедрі, якій потрібен один спільний контрольний список, перш ніж хтось опублікує інструмент для студентів, і викладачам, які навчають [[ai-literacy|ШІ-грамотності]] через творення, а не через критику.

## Примітки та застереження

Центр — це настанова, а не продукт відповідності: сайт не заявляє відповідності власній цілі WCAG 2.2 AA, на питання «чи робить використання цих файлів мій сайт відповідним?» відповідає «ні» й каже, що інженерний огляд не замінює шкільного дозволу чи юридичної перевірки. Полиця безпеки вказує на axe-core, Gitleaks, ZAP і Playwright; це посилання, а не вбудоване програмне забезпечення, і інвазивні з них призначені для одноразової або явно дозволеної цілі. Читання не потребує облікового запису. Перезбирання HTML-сторінок потребує Python і `markdown-it-py`, що є залежністю збирання, а не залежністю відвідувача. Репозиторій ліцензовано під MIT, тоді як сторонні ілюстрації й пов’язані проєкти зберігають власні умови, задокументовані в `CREDITS.md`.

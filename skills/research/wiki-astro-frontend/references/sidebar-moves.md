# Sidebar / TOC moves, renames, and label changes (validated 2026-08-31)

Recurring maintainer requests are to **move a concept between sidebar sections** (with or without a rename) or **rename a sidebar group label**. All three were exercised repeatedly on 2026-08-31. The canonical reorg doc is `src/data/conceptIndex.ts`; the EPUB/PDF TOCs are ALSO generated from it, so offline exports must be regenerated on any move.

## Three request variants (all common)
1. **Rename + move** (e.g. "Misconceptions about AI"): change title, move slug between groups, and often broaden the concept body.
2. **Pure move** (no rename): just relocate the slug in `conceptIndex.ts` (examples that session: `ai-use-disclosure` → Equity/ethics>Ethics-and-responsibility; `prompt-engineering` → AI-technologies>Models-and-techniques; `technology-acceptance-model` → People>Institutions-and-systems; `guardrails`+`privacy` → Ethics-and-responsibility; `learning-analytics` → Learner-modeling-and-adaptive-systems; `critical-thinking` → Cross-cutting-themes; `critical-pedagogy` → Learning-and-instruction>Core-pedagogies).
3. **Group-label rename** (e.g. "Teachers" → "Instructors"): change the `label:` string only; item slugs unchanged.

## Steps for ANY variant
1. **`concepts.registry.yaml` `sections:` block is the source of truth** — remove the slug from the old group's `items:` list and add it to the new group's, at the position you want in the sidebar (list order = sidebar order). `src/data/conceptIndex.ts` is **generated** from that block (`gen-concept-artifacts.py`) and its header says so; hand-editing it is overwritten on the next regeneration. For a label rename, edit only the `label:` string. Run `python3 tooling/scripts/gen-concept-artifacts.py` afterwards — it writes the sidebar module and the EPUB/PDF TOC source.
1b. **Reroute the facet value on every page that carries the moved node — a move changes which field may hold it.** Facet fields map one-to-one to registry sections, so moving `sustainability` out of Foundations means every page with `foundations: [..., sustainability]` must become `ethics: [..., sustainability]` or `validate-facets.py` fails (2026-09-19: 9 pages for sustainability, 41 for pedagogical-safety, whose value left `stakeholders:` for `ethics:`). Find them by scanning frontmatter for the slug, not by grepping the body. Drop the field entirely when it becomes an empty list.
1c. **Regenerate the SCHEMA.md vocabulary block** (`python3 tooling/scripts/audit-metadata.py --write-docs`, then `--check-docs` to prove it) — its per-field slug lists drift silently: this session's `stakeholders:` line was missing `learners` and still listed seven slugs that had moved to other sections. Follow order: registry → `gen-concept-artifacts.py` → `--write-docs`, or the doc is regenerated from the stale generated vocabulary.
2. **`concepts/ai-education.md` umbrella narrative** — this page mirrors the sidebar section headings and must stay in sync: move the concept's mention to the matching `## section` bullet/paragraph; for a label rename update the umbrella's `**Label:**` bullet (e.g. `**Teachers:**` → `**Instructors:**`, and `**Instructors:**` → `**Instructors and teaching frameworks:**`); update the `## Connected Concepts` descriptor if the old label reads differently. Bump the page's `updated` (full ISO). Note the umbrella sometimes carries the concept twice (a cross-cutting-themes paragraph AND a section bullet) — remove it from the old mention, do not just add the new one.
2b. **A long index/journal/log entry is usually needed**: `index.md` (one line per page) and `journal.md` (📘 for a concept, 📄 for an article) both need the new entry, and `log.md` records why the move happened (the counts that justified it).
3. **Regenerate `llms.txt`/`llms-full.txt`** (`python3 tooling/scripts/generate-llms-files.py`) — the generator sorts concepts by sidebar order, so a move changes the LLM-file order.
4. **Do NOT auto-regenerate the EPUB/PDF** after a sidebar move or label change (2026-09-08): epub/pdf are local committed artifacts rebuilt ONLY on explicit request. `build-epub.py` parses `conceptIndex.ts` for chapter/group structure, so if an epub/pdf rebuild is directed AFTER a move/label change, regenerate then — but do not run it proactively; the drift risk is accepted until asked. (Still run step 3 for llms files, which are cheap and always kept in sync.)
5. **Verify in the built HTML** — after `npm run build`, check `dist/index.html` (or the live page): the slug sits inside the new group's nav block (after that group's label `<div>`) and is ABSENT from the old group's block. Verify programmatically rather than eyeballing: `h.find('<NewLabel></div>')` then check the slug substring in that slice, and the inverse for the old label.
6. **Commit the .astro/.ts + content + llms + epub/pdf together** in one commit. Only the files you touched should appear in `git status` — if many unrelated files are dirty, a concurrent ingester cron may be running (see `concurrent-git-worktree-safety`); commit only your files.

## Naming conventions to keep
- Prefer clean, class-level labels; the maintainer renamed "Teachers" → "Instructors" (2026-08-31) — use "Instructors" for educator stakeholder groups.
- When a concept's slug stays the same but its grouping changes, do NOT rename the slug — only edit `conceptIndex.ts` membership (renaming a slug breaks inline links/redirects; see `wiki-concept-page-design`).

## Cross-linking note (moves often pair with link fixes)
When the maintainer asks "shouldn't X link to Y concept?", treat it as a bidirectional-link check: add the reciprocal link on the target concept page too (one-way links are flagged). E.g. an article about course-policy co-design should link `[[educational-policy-ai]]` (not `[[governance]]`) for "policy-making", and `educational-policy-ai` should list the article back in its Connected Articles.
